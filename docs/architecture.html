Factory Inventory Management

System architecture, tech stack, and data flow

System Overview

A two-tier demo application. A Vue 3 single-page app talks over HTTP to a FastAPI service that serves in-memory data loaded from JSON files. There is no database.

Data Flow

How a filter change on screen becomes new data on screen.

  1. User changes a filterFilterBar updates shared refs in useFilters (period, warehouse, category, status). They are module-level singletons, so every view sees the same state.
  2. View reloads dataThe view calls getCurrentFilters() and passes the result to an api method. Period is sent as month.
  3. api.js builds the requestFilters set to all are dropped; the rest become query params on GET /api/....
  4. FastAPI filters in memoryThe handler runs apply_filters (warehouse, category, status) and filter_by_month (month or quarter) over lists loaded at startup.
  5. Pydantic validates the responseThe response_model serialises the list back to JSON.
  6. Vue re-rendersResults land in refs (allOrders, inventoryItems); KPIs and charts are computed properties derived from them.

Startup sequence

  • main.py imports mock_data.py
  • mock_data.py reads every JSON file in server/data/ once
  • Lists become module-level globals shared by all requests
  • Edits to the JSON files need a server restart

Frontend Structure

Routes

  • / Dashboard
  • /inventory
  • /orders
  • /spending
  • /demand
  • /reports

Backlog.vue is a view file but has no route; backlog is reached through the dashboard.

Shared state (composables)

  • useFilters global filters
  • useI18n locale, currency (USD or JPY), saved in localStorage
  • useAuth mock current user

Conventions

  • Raw data in refs, derived data in computed
  • Unique keys in v-for, never index
  • Validate dates before .getMonth()
  • No emojis in the UI

Known Gaps

Mismatches found while reading the code that are worth knowing before you build on it.

Missing backend routes. api.js calls /api/tasks (GET, POST, PATCH, DELETE) and /api/purchase-orders (POST, GET by backlog item), but main.py defines none of them. The Pydantic models PurchaseOrder and CreatePurchaseOrderRequest exist and purchase_orders.json is empty, so this looks like unfinished work. The tasks modal falls back to mock tasks from useAuth.
Demo-grade security. No authentication, CORS allows all origins, and the API base URL is hard-coded to localhost:8001 in api.js and Reports.vue.
Duplicated logic. Quarter-to-month mapping is implemented twice in main.py (QUARTER_MAP and an if-chain in get_quarterly_reports).
